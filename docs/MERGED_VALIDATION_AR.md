# نتائج التحقق — WolFox GPS Merged 3.1.1

## نتيجة البناء

نجح البناء المحلي باستخدام Java 17 وAndroid SDK 34 وBuild Tools 34.0.0. يتضمن الناتج R8 لتصغير الأسماء الداخلية مع بقاء `WolFoxHook` و`DirectBootstrap` بأسمائهما بوصفهما نقطتَي دخول خارجيّتين. جرى تجميع المصدر أيضًا مقابل **Xposed API 82 الرسمي** للتحقق من توافق توقيعات الاستدعاءات، لا stubs المحلية وحدها.

أُكمل مسار Gradle بتبعية `compileOnly` لـXposed ومكتبات اختبار معزولة، وأضيف Gradle Wrapper 8.9. لا توجد فئات تنفيذ Xposed داخل DEX؛ إطار المضيف يجب أن يوفرها وقت التشغيل.

- الحزمة: `com.wolfox.gps`.
- الإصدار: `3.1.1`، versionCode: `313`، كما في الأصول.
- min SDK: `21`، target/compile SDK: `34`.
- APK: غير قابل للتصحيح في البناء المحلي المصغّر، **بتوقيع اختبار** وليس مفتاح المستخدم الأصلي.
- حجم APK: `640009` بايت.

## اختبارات Android المحلية

**نجحت 24 من 24 اختبارات، بصفر فشل أو أخطاء أو اختبارات متخطاة.** استخدمت JUnit وRobolectric على API 34.

- 12 اختبارًا للأيقونة: الأصل PNG قابل للفك ويستخدم ImageView؛ مخفية افتراضيًا؛ استئناف الشاشة لا ينشئ طلب ظهور؛ الطلب مرتبط بعملية التشغيل؛ الإظهار لا يكرر العنصر؛ الإخفاء يظل مخفيًا عند الاستئناف؛ قيمة PID/وقت بدء قديمة لا تعيد الظهور؛ فصل الشاشة المتوقفة ثم الاستعادة فقط عند وجود الطلب؛ الضغط الطويل 850ms؛ إلغاء الضغط القصير؛ أوامر show/hide الصريحة؛ منع مؤقت hide قديم من إلغاء show جديد؛ تأكيد الإخفاء؛ وربط النقر باللوحة أو التفعيل حسب الحالة المحلية. بعض الاختبارات تغطي أكثر من شرط من هذه الشروط، وعددها 12 لا عدد الشروط.
- 4 اختبارات لمحرك GPS: `buildLocation` يعيد الإحداثيات وخصائص العينة مع `isMock()==true`؛ نتائج رفض الترخيص غير النشط، وعدم وجود موقع، وعدم وجود runtime marker. لا تُصطنع نتيجة نجاح hooks.
- 3 اختبارات لحالة الترخيص المحلية: انتهاء Active إلى Expired، رفض Disabled، وReset/مسح الترخيص يوقف حالة التزييف.
- اختبار UI واحد للزر الصريح «تزييف الموقع»: النص والوصف وtag الصحيح، واستجابة الضغط عند غياب الموقع مع بقاء الزر جاهزًا وإيقاف التزييف.
- 4 اختبارات لمدخلات روابط الخرائط والإحداثيات والحدود والمدخلات غير الصالحة.

الحالة Active في بعض الاختبارات **fixture محلية غير إنتاجية** فقط؛ لم تُنشأ أكواد تفعيل حقيقية ولم تتغير بوابة `LicenseManager.isActive` في المصدر. لم تُستدعَ واجهات التفعيل أو التحقق الشبكي أثناء الاختبارات.

## حواجز المصدر

نجحت 8 سكربتات انحدار مراجعة قبل تشغيلها: اتساق الهوية والإصدار، دورة الأيقونة، إنفاذ الانتهاء، عدم استدعاء Root، توافق مزودي Location المدعومين مع علامة Mock، خريطة المفضلة للقراءة فقط، ترتيب فحص runtime والزر، والإظهار الصريح فقط.

هذه حواجز **ساكنة**، ولا يُدّعى أنها تثبّت hooks داخل عملية Android حقيقية. إصلاح runtime probe يضع علامة Mock قبل قراءة getters، بدل اختبار كائن غير معلّم قد يسبب إيقافًا كاذبًا. لا توجد hooks لإجبار `isMock` أو `isFromMockProvider` على false.

## Android Lint

النتيجة النهائية: **صفر أخطاء و46 تحذيرًا**، وليست نتيجة خالية من التحذيرات.

عُولجت أخطاء تلوين Switch المتاح من API 23 بحارس إصدار، مع إبقاء min SDK 21. حُصر استثناء `HardcodedDebugMode` في Application لأن البناء المحلي المباشر يحتاج `debuggable=false` صريحًا؛ فحص Manifest الثنائي يتأكد من القيمة بدل افتراضها. عُطّل Jetifier لعدم وجود مكتبات دعم قديمة، بعد تعارضه مع dependency اختبار متعددة إصدارات Java.

التحذيرات المتبقية تشمل انعكاس APIs خاصة في hooks، references ثابتة لدورة الحياة/الحوارات، target SDK الأصلي، strings عربية ثابتة، commit متزامن للحالة الحرجة، JavaScript الداخلي للخريطة، واتجاه النص. لم تُعطّل Lint ككل ولم تُخفَ جميع التحذيرات.

لا يحتوي الموديول على Launcher Activity؛ الأيقونة المقصودة هنا **الأيقونة العائمة داخل المضيف**. الأصل المرفق معبأ ويستخدم في واجهة الأيقونة، لكن لا يوجد رمز Launcher لتطبيق مستقل.

## فحص APK

نجح `apksigner verify` بمخططات v1 وv2 وv3. شهادة اختبار:

```text
CN=WolFox Test Module, OU=Testing, O=WolFox, C=SA
```

SHA-256 للشهادة:

```text
1b59c4e9d47af951bf7b541f74345edde3b45569d67f43a27de6221816d0b70b
```

SHA-256 لملف APK النهائي:

```text
2f91360c17cb76213a5e574c1a669469b712ff5dacf88969efcbbcaacad616bd
```

تم التحقق من ZIP وDEX وmapping المحلي: نقاط الدخول باقية، أسماء المحرك الداخلية مصغّرة، وJavaScript bridge `resolve` لم يُعد تسميته. الأصول الأربعة تطابق مصدر الدمج حرفيًا: `wolfox_icon.png` و`wolfox_map.html` و`xposed_init` و`lspatch_module_info.json`.

لا توجد Java/Class sources أو mapping أو مفاتيح JKS/keystore أو Xposed stubs داخل APK. قيم `debuggable` و`allowBackup` و`usesCleartextTraffic` كلها false في Manifest الثنائي.

أذونات Manifest المطلوبة ثلاثة: INTERNET وACCESS_FINE_LOCATION وACCESS_COARSE_LOCATION. لا يوجد ACCESS_MOCK_LOCATION أو WRITE_SECURE_SETTINGS أو SYSTEM_ALERT_WINDOW أو صلاحيات تثبيت/إدارة أو استدعاءات `su`/Root. عدم وجود هذه الاستدعاءات لا يغني عن الحاجة إلى إطار تحميل hooks متوافق.

## ما لم يُختبر

لم يُثبّت APK على هاتف أو يُشغّل داخل LSPosed/LSPatch أو داخل التطبيق المضيف. لم يُعدّل أو يُوقّع APK المضيف، ولم يُجرَ اتصال بخادم الترخيص أو تجربة كود فعلي أو Android 16 فعلي. لذلك **لا يوجد ضمان تشغيل نهائي على جهاز المستخدم** من نتائج الوحدة وحدها.

يمكن تشغيل الموديول دون خيارات المطوّر لأنه لا يستخدم TestProvider، لكن التشغيل بلا روت يحتاج بيئة تحميل مضيف تعمل بلا روت. تثبيت APK وحده لا ينشئها، ولا يغيّر الموقع للنظام أو جميع التطبيقات. النطاق المصرّح به في المصدر لم يُوسَّع.

اختبار القبول التالي على الجهاز المصرّح به: تأكد أن الفتح الأول لا يظهر الأيقونة؛ استخدم الضغط المطوّل لإظهارها؛ فعّل بترخيص صالح؛ حدّد موقعًا واضغط «تزييف الموقع» وتحقق من حالة النجاح أو الفشل؛ أوقف التزييف؛ أخفِ الأيقونة وبدّل الشاشات؛ ثم أغلق العملية وافتحها وتحقق أنها مخفية حتى أمر جديد. انتهاء/تعطيل الترخيص يجب أن يمنع التشغيل ويوقف الجلسة، دون إعادة إظهار قسرية للأيقونة.

المصدر المسلّم يستبعد `local.properties` ومفاتيح التوقيع وmapping الخاص وملفات CI الأصلية ومجلدات build والكاش. الأرشيفات الخمسة المرفقة بقيت ببصماتها الأصلية دون تعديل.
